Knowledge Discovery — Design Direction Review · Turn 1

Signature Visual — 3つのDirection

前提: 既存UIの改善ではなく、Product Conceptからゼロで再設計。共通の憲法は Humans are large. Agents are small. — AIの活動はevidenceであり主役ではない。各Directionは 1a / 1b / 1c、最終判断は 1d。

1a Direction A
Organization Map

The Company Atlas

Design thesis: 会社を一枚の地図として描き、部署という境界線を「実在するが越えられる線」として見せる — connectionとは、地図上に新しい道が引かれることである。

3–4 · Signature Screen — Bridge Trace = 組織の地図

構図: 地図が画面の約80%。Timeline/auditは下部drawer(常時1行のサマリのみ)。左sidebarは既存のまま。

5–10 · Visual Vocabulary
Department
地図上のregion。塗りではなく破線の境界線 + letterspaced caps のラベル(地図の地名表記)。壁として実在するが、薄い。
Human
インクの点。名前はserifで、地図上で最も濃い要素。関与が深いほど点が大きく、名前が大きい。
Agent
人の脇に添えられた直径3pxの中空の鉛筆マーク。地図に書き込まれた測量士の注記であり、地形ではない。
Need detected
Jordanの点から広がる同心円のripple(surveyor blue、1本ずつ静かに)。radar sweepの回転線は使わない — 波紋であって走査ではない。
Search
rippleが届いたregionのラベルがinkに変わり「目を覚ます」。該当者の点がわずかに拡大。落選者は評価理由と共に元の薄さへ戻る。
Connection
境界線を跨いでterracottaの実線の道が引かれる。地図に道が1本増える = プロダクトの成果物。
11–13 · 他画面とのContinuity

My Agent: ヘッダー背景に自分の周辺だけを描いたminimap(半径2 region分)。Need検知時、カード表示より先にminimapでrippleが始まり、Bridge Traceへの連続性を作る。

Connection Request (Marcus側): 冒頭に小さな地図の断片 —「OperationsのJordanからあなたのregionへ届いた線」。どこから来た依頼かが地理的に分かる。

Connection Created: 地図全体がフェードし、2つの点と1本のterracottaの道だけが残る。キャプション「A path that didn't exist yesterday.」

14 · Color System —「紙とインク」

論拠: 地図の権威と静けさは「紙 + インク」から来る。彩度の高い色は connection の1色だけに独占させ、「人間関係の成立だけが色を持つ」というPhilosophyをパレット構造そのものに刻む。

Agent · 鉛筆 #8A8371(中空・消せる注記)

15–17 · Typography & Motion

Type: 人名 = Source Serif 4(地図上で人間だけがserif = 人間だけが固有名詞)。Department = Archivo caps + letterspacing 3px(地名表記)。UI本文 = Archivo。Agentの注記 = 11px graphite。この4層のhierarchyがそのままPhilosophyの序列。

Motion: 平常時は完全に静止(pulse dot 1つのみ)。Need → ripple 3周(各1.8s、ease-out)→ region覚醒(ラベルの色が0.6sでインク化)→ 候補の点が浮上 → 落選がフェード → terracottaの道が1.2sで描画(stroke-dashoffset)→ Created時に地図ごとフェードして2点1線が残る。

Demoの最強の瞬間: rippleが部署の破線を越える一拍。「境界は実在するが、signalは越える」が1カットで伝わる。

18–22 · Judgment
非generic性
AI SaaSに「会社の地図」は存在しない。node graphでもdashboardでもなく、cartographyという別の視覚言語を borrow している。
Enterprise成立
紙 + インク + 測量は年次報告書・組織図の伝統に接続する。むしろ既存SaaSより保守的に見える。
Risk
regionレイアウトが恣意的に見える危険。部署数が多いと地図が崩れる。「座席表・監視」に誤読されないようreal officeの地理とは無関係だと明示する必要。
実装難易度
中。regionは静的な手置きレイアウト(デモは1社固定)で成立。SVG + CSS animationのみ、物理シミュレーション不要。
既存UI残存率
~70%。shell / cards / type scale / terracottaの意味は温存。Bridge Traceの2カラムを地図 + drawerに置換、My Agentヘッダーにminimap追加。
1b Direction B
Latent Network

The Latent Field

Design thesis: 組織には見えないHuman Networkが既に存在する — Needが生まれた瞬間だけ、その一部が暗い場から浮かび上がる。

3–4 · Signature Screen — 光の井戸としてのcanvas

構図: 光のchrome、闇のcanvas。アプリshellは既存の温かい紙のまま、Bridge Traceの窓だけが「組織の潜在層を覗く井戸」として暗い。1画面内のコントラストがそのままconcept(見える業務 / 見えないnetwork)。

5–10 · Visual Vocabulary
Department
星座のまとまり。境界線は描かず、点の密度と薄いラベルで領域を示す(星座に国境はない)。
Human
光の点。関与すると点が明るく・名前がserifで浮かぶ。未関与の399人は暗い場のtexture。
Agent
点そのものではなく、点の間を走る細い調査線。人=光、agent=線、と役割を完全分離。
Need detected
Jordanの点が呼吸のように明滅し、柔らかいcyanのハローが1周広がる。
Search
relevanceの高いregionの点群が段階的に目を覚ます。落選した点は理由のtooltipを残して眠りに戻る。
Connection
全ての調査線が消え、amberの1本線だけが残る。「星座に新しい線が加わる」。
11–13 · 他画面とのContinuity

My Agent: Need検知カードの端に小さな暗い窓(現在の探索の縮小live view)。クリックでBridge Traceへ。

Connection Request: Marcusの画面上部に「あなたが今、誰かの空で光っている」ことを示す小さな星座片。承諾前はJordan側の詳細は見えない。

Connection Created: 暗い場全体が明るい紙にfade — 潜在層から日常へ戻り、amberの線だけが紙の上に残る。

14 · Color System —「夜の場、昼のchrome」

論拠: 「見えないものが浮かび上がる」は暗い地の上でしか成立しない。ただし全画面dark UIにするとAI toolのクリシェになるため、闇はcanvasの1領域に閉じ込める。

15–17 · Typography & Motion

Type: Aと同じ2書体戦略(serif=人名、grotesk caps=領域)。暗いcanvas上では人名serifがほぼ唯一の「文字」で、闇の中の名前という強い画になる。

Motion: quiet(点の0.5%だけが時折瞬く)→ Need(Jordan明滅 + ハロー1周)→ 覚醒(点群が0.4s stagger で点灯)→ 絞り込み(落選が2sかけて減光)→ amber線の描画 → 全調査線消灯。粒子・回転・常時アニメは無し。

Demoの最強の瞬間: 承諾直後、数百の点が一斉に眠り、amberの1本線だけが闇に残る2秒間。

18–22 · Judgment
非generic性
light chrome + dark canvasの同居は珍しい。ただしnode graph自体はAI demoの既視感が強く、ここが最大の弱点。静止画1枚ではObsidian / Neo4jに誤読されうる。
Enterprise成立
chromeが既存の紙UIのまま残るため、全体の信頼感は保たれる。canvasはあくまで1つの計器。
Risk
generic graph vizとの区別が「動き」に依存する。静止画勝負(Devpost)で不利。監視的に見えるリスクもAより高い(暗所で人が光る=検出のメタファーに近い)。
実装難易度
中〜高。点群レイアウト・stagger・減光の制御。CSS + SVGで可能だが調整コスト大。
既存UI残存率
~80%。chromeはそのまま。Bridge Traceのcanvas差し替えが中心。
1c Direction C
独自案 · The Introduction

The Introduction — 見開きの紹介状

Design thesis: このプロダクトの成果物はnetworkでもdashboardでもなく「1通の紹介」である — 画面を、2人の人間が向かい合う見開き(book spread)として設計し、AIの全活動を脚注に格下げする。

3–4 · Signature Screen — 紹介状の見開き

構図: 2人の人間が本の見開きの左右ページ。間の線は「まだ引かれていない」(破線→承諾で実線)。AIの全仕事は書誌学の脚注¹²³としてページ下部に。脚注というメタファー自体が "AI activity is evidence" の直訳。

5–10 · Visual Vocabulary
Department
人名の下のletterspaced capsの所属表記(名刺・蔵書票の流儀)。空間ではなく肩書として存在。
Human
ページの主。serif大組みの名前 + 一人称で書かれたneed/experienceの1文。
Agent
脚注番号(¹²³)。本文には現れず、根拠として参照されるだけ。
Need detected
左ページだけが先に「書かれる」— タイプライター的に1文が現れ、右ページは空白のまま。
Search
右ページに候補の名前が薄く重なって現れては消え(20→4→1)、最後にMarcusが定着する。
Connection
破線がsealing-wax redの実線になり、日付が刻印される —「Introduced · Mar 14, 2026」。
11–13 · 他画面とのContinuity

My Agent: Need検知は「左ページが書かれ始めた」通知。ページの断片がカードとして現れる。

Connection Request: Marcusは同じ見開きの右ページ側から見る。左ページ(Jordan)は承諾まで要約のみ。対称性がプライバシー設計そのもの。

Connection Created: 見開きが閉じて1枚のカードになる — 2つの名前、1本の線、日付。組織の「紹介の台帳」に積まれていく。

14 · Color System —「書簡」

論拠: 紹介状という私的で丁寧な文書の色。インクと封蝋以外の色を持たないことが誠実さの表現。

15–17 · Typography & Motion

Type: 3案中もっともtypography主導。人名 = Source Serif 4 semibold 大組み。need/experience文 = serif italic(人の声)。脚注 = serif 小組み(AIの声は常にこのスタイル)。UI操作系のみ Archivo。書体がそのまま「誰が話しているか」の表明。

Motion: 文字が書かれる速度のmotion。左ページ執筆 → 右ページで候補名が入れ替わり定着 → 破線が実線へ(0.9s)→ 日付スタンプ。アニメ対象はほぼテキストと1本の線のみ。

Demoの最強の瞬間: 空白だった右ページにMarcusの名前が定着する瞬間 —「組織があなたの問いに答えた」。

18–22 · Judgment
非generic性
graph も map も dashboard も使わない唯一の案。AI SaaSの語彙が画面に1つも無い。
Enterprise成立
紹介状・推薦状はビジネスの最古のUI。役員に最も説明しやすい。
Risk
「組織全体を探索した」規模感が画面から消える(脚注の数字でしか語れない)。Devpostの静止画では「きれいなプロフィールカード」に見える危険。autonomous agentの技術的凄みが伝わりにくい。
実装難易度
低。ほぼtypographyとレイアウト。3案中最速。
既存UI残存率
~60%。person card / status系は書簡様式に組み直し。shellは残る。
1d Design Director's Verdict
Q1 · Devpostに載せる1枚

1a の Bridge Trace(探索中盤: rippleが境界を越え、Marcusが浮上した瞬間のフレーム)。地図 + 部署ラベル + 波紋 + 境界を跨ぐ1本の線 + 「400 → 20 → 4 → 1」が1枚に同居し、名詞(組織)・動詞(探索)・成果(接続)が全部写る唯一の画面。

Q2 · 3秒で伝わるか

伝わる。読み順が設計されている: ①「会社の地図だ」(部署ラベル)→ ②「誰かから信号が出ている」(ripple)→ ③「別の部署の人と繋がった」(境界を跨ぐ線)。3ステップとも文章を読まずに図像だけで成立する。BはObsidian、Cはプロフィールカードに誤読される余地が残る。

Q3 · 固有のプロダクトか

「自社の地図の上で、自分の代わりに誰かを探してくれた」という画は他のどのAI SaaSにも属さない。cartographyの語彙(紙・インク・破線境界・地名caps)はnode graphの語彙と根本的に違うため、模倣元が想起されない。

Q4 · 受賞作と並んで「世界」があるか

Agentropolis=City、MLB=Field、INTER=Room に対し、Knowledge Discovery=Company Atlas。「このプロダクトの中では会社は地図である」という世界の定義を持てる。Bは世界ではなく計器、Cは世界ではなく文書。

最終判断 — Direction A「The Company Atlas」を採用

理由は3つ。①スクリーンショット1枚テストに勝つのはAだけ — Bの価値は動きに、Cの価値は読むことに依存するが、Aは静止画で全文が伝わる。②Product Problemが構図に内蔵されている — 「同じ会社にいても出会えていない」は、破線の境界と、それを跨ぐたった1本の線という構図そのもの。③Philosophyがレイヤー構造で守られる — 人=インク(最濃)、部署=地名(中)、agent=鉛筆の注記(最薄)。AIは地図に書き込む測量士であって、地形ではない。

なお採用後、Bの「落選ノードの減光」とCの「脚注としてのagent evidence」は思想としてAの演出・trace drawerの文体に反映できるが、視覚言語の混合はしない — canvasはあくまで地図1本。次の一手: Bridge Trace signature screenのhi-fi 1枚(静止)→ 承認後にNeed→Connectionのmotion prototype。
