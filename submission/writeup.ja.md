## インスピレーション（Inspiration）

人、人、人——AIエージェントが私たちの代わりに仕事をしてくれる時代が目前だ。私たち人間は何をするのか？

「人間を人間たらしめるもの: 愛し、愛されること」（[Kai-Fu Lee, *AI Superpowers*, 2018](https://www.goodreads.com/work/quotes/59924665-ai-superpowers-china-silicon-valley-and-the-new-world-order)）
「人間は、人間を気にかけるようにできていると分かるだろう」（[Sam Altman, MIT, 2024](https://mitsloan.mit.edu/ideas-made-to-matter/sam-altman-believes-ai-will-change-world-and-everything-else)）

AIを作っている当人たちの答えは揃っている。そう、人と人の繋がりだ。

企業も同じ答えに賭けた。パンデミックを乗り越え、協働を取り戻すことを最大の理由に掲げて、出社回帰が始まった——92%の企業が対面協働を出社のメリット上位に挙げ、35%が「もっと協働してほしい」を出社方針の一番の理由にした（[WeWork, 2023](https://www.wework.com/newsroom/leaders-desire-for-more-in-person-collaboration-is-driving-the-return-to-office-wework-survey-finds)）。しかし、同じ建物にいることと繋がっていることは同じではない。Atlassianの行動科学チームは1,600回以上のチーム集合を計測し、散発的なオフィス出社はチームの連帯感に測定可能な効果を持たないことを示した（[Atlassian Teamwork Lab, 2024](https://www.atlassian.com/blog/distributed-work/intentional-togetherness-research)）。MITの18か月にわたる因果研究では、新しい仕事上の繋がりが生まれるのは150メートル以内の近接だけ。それを超えると、有意な効果は消えた（[Carmody ほか, *Nature Computational Science*, 2022](https://doi.org/10.1038/s43588-022-00296-z)）。数千人規模の企業なら、同僚のほとんどは確実に150メートルの外側にいる。

だから人は探し回る。知識労働者は毎週1.7時間を、質問に答えられる「適切な人」を探すことだけに費やしている（[APQC, 2021](https://www.apqc.org/about-apqc/news-press-release/apqc-survey-finds-one-quarter-knowledge-workers-time-lost-due)、n=982）。28%は、組織が大きすぎてそもそも誰が答えを持っているか分からない（[Forrester/Starmind, 2022](http://web.archive.org/web/20240130042729/https://www.starmind.ai/hubfs/Assets%202022/Forrester-Opportunity-Snapshot-2022.pdf)）。56%は、必要な情報を得る唯一の方法は誰かに聞くか会議を設定することだと言う（[Atlassian State of Teams 2025](https://atlassianblog.wpengine.com/wp-content/uploads/2025/03/the-state-of-teams-2025.pdf)、n=12,000）。27%の企業は、LinkedInの方が自社より従業員のことを知っていると認めている（[i4cp, 2021](https://www.i4cp.com/press-releases/study-only-30-of-companies-say-their-employees-have-needed-skills-but-few-understand-current-capabilities)）。

転回点は、パリの古いキャンパスにあった。アスベスト除去工事のせいで、ジュシュー・キャンパスの研究室は15年間に5回、行き先も選べないまま引っ越しさせられた。誰の隣になるかは、ほぼ偶然。その結果、隣り合ったラボの共同研究は3.5倍に増えた。効果は「もともとお互いを見つけにくかったペア」に集中していた。そして一度組んだペアは、引き離されても共同研究をやめなかった（[Catalini, *Management Science*, 2018](https://doi.org/10.1287/mnsc.2017.2798)）。近接は魔法ではなかった。探索コストの低下だった。見つかりさえすれば、距離はもう関係ない。

探索コストなら、AIで下げられる。人に聞くのは今も正しい。分からないのは「誰に」だけだ。だから私たちは作った——探すのはAI、会うのは人間、というシステムを。

## 何をするものか（What it does）

すべての従業員に、個人のAIエージェントが付く。普段は、どこにでもいる秘書だ。今日の締め切りを並べ、メールから拾ったことをプロフィールに足しておきましょうかと聞いてくる。その程度の、よくあるやつだ。

Jordanは悩んでいる。顧客から、まるで畑違いの依頼が来たのだ。「同じグループで、その事業もやっているでしょう」——理由はそれだけ。無下に断るわけにはいかない。かといって、その分野を知っている同僚を探して回る時間は、彼女にはない。「確認してご連絡します」と返したきり、タスクは机の隅で塩漬けになる。

そこに、彼女のエージェントが静かに気づく。ここから、動きが変わる。

400人の会社なら、400のエージェントがいる。彼女のエージェントは心当たりのありそうな相手に見当をつけ、尋ねて回る——「この件、あなたの主人は力になれる？」。尋ねられた側のエージェントは、自分の主人について知っていることをもとに答える。主人しか知らない事情で「力になれる」と分かっても、中身は明かさない。答えるのは、あるか、ないか、だけ。

候補が一人に絞れたら、エージェントは紹介の下書きを作る。そして、止まる。画面にはこう書いてある——*Introduction prepared, not sent*。準備はできた。送ってはいない。Jordanが下書きを読み、直し、「15分ください」と押すまで、誰にも何も届かない。人に連絡する判断だけは、仕組みの上で人間に予約されている。

相手のMarcusに届くのは、通知でもチケットでもなく、一通の紹介状だ。誰が、なぜあなたを、何を共有して、何を守ったまま。承諾してもいい。代わりに資料を渡してもいい。静かに断ってもいい——断ったことはJordanに見えない。繋がりが生まれるのは、双方がうなずいたときだけ。

そして組織は、一枚の海図になる。Company Atlas。部署は島、人はインクの点、エージェントの働きは細い破線。人間は大きく、エージェントは小さく描かれる。AIが見つけたルートは破線のまま。実線の橋を架けられるのは、人間同士の同意だけだ。エージェントたちが裏で何をしたかは、監査ビュー Bridge Trace でいつでも追える。

## 試す（Try it）

デモは Cloud Run 上で、今も動いている。デモの世界では、"Jordan" は医療人材紹介のマネージャ。届いた畑違いの依頼はクリニック移転——不動産の話だ。それを二度やったことのある同僚は、まったく別の島にいた。

`/requester` が Jordan の画面。`/candidate` が Marcus に届く紹介状。`/audit` が Bridge Trace。キー入りのリンクは提出フォームのテスト手順欄にある。依頼から承認、応答、監査まで、ひとつのリンクで通して回せる。データはすべて合成です。

## どう作ったか（How we built it）

**Gemini + Google Cloud で一気通貫**。基盤は Gemini Enterprise Agent Platform（GEAP、旧 Vertex AI）。プロジェクトは `knowledge-discovery-2026`、東京リージョン（asia-northeast1）。

- **Cloud Run** — FastAPI サービス。エージェント間のメッセージング、秘書のパイプライン、3つの画面、全部ここに載っている。なぜ GKE や Cloud Functions でないか？ サービス全体がステートレスなコンテナ1つで足りるからだ。クラスタ運用なしで、認証付き HTTPS・スケールゼロ・Scheduler との OIDC 連携が揃う。
- **Cloud Scheduler → OIDC → `/internal/autonomous-sweep`** — 30分ごとの無人実行。署名・audience・issuer・呼び出し元サービスアカウントを検証し、API キーは受け付けない。なぜ Pub/Sub や Cloud Tasks でないか？ 欲しいのはキューではなく cron そのものだからだ。OIDC トークンは共有シークレットなしで呼び出し元を証明し、スケジュールスロットはそのまま冪等性キーになる。
- **Gemini 3.7 Flash** — 質問ドラフトと、候補者ごとの関連性判定。なぜ Pro 系でないか？ 候補者を隔離する設計上、1回のスイープで最大20回の小さな判定が走る。効くのは応答速度と単価で、安全性はモデルの賢さではなく、フェイルクローズドなスコア検証で守る。
- **gemini-embedding-2 on GEAP** — プロフィール検索。類似度フロア 0.62 は、このモデル向けに校正した値だ。なぜ Gemini API 直でないか？ ADC/IAM で認証すれば、API キーをコードにも環境にも置かずに済む。推論はデータと同じプロジェクト、同じガバナンスの内側にいる。
- **Firestore（native）** — プロフィール×400、エージェント、タスク、カード、自律性ポリシー、スイープの実行クレーム。そして追記専用の監査ログ `messages`。なぜ Cloud SQL や AlloyDB でないか？ プロフィールは人ごとに項目も可視性も違う「ドキュメント」だからだ。スキーマ移行なしで設計を回せて、トランザクションは冪等性クレームの CAS にそのまま使える。テナント分離は named database。
- **GEAP Agent Runtime（Agent Engine・ADK）** — 秘書はマネージドエージェントとしても第一級で動く。スケジュール実行は決定論的に同じスイープ API を叩き、対話エージェントは読み取り専用。GEAP Agent Registry には6エージェント。なぜ Cloud Run に自前のループを書かないのか？ 統治のためだ。エージェントをプラットフォームの第一級市民として登記しつつ、配送権限だけは意図的に Runtime へ渡さなかった。
- **オフラインテスト323件** — 外部サービスは全部インターフェースの向こう側。決定論的なフェイクで、ネットも認証情報もなしにスイートが走る。

その他のデータソース: ない。会社も401人も、プロフィールもタスクもメールも、全部スクリプトが生成した合成データだ（架空の Meridian Care Partners Group）。埋め込みはシード投入時に GEAP で計算する。実データは1バイトも使っていない。

## セキュリティの物語（なぜ "Fortified" か）

承認は構造にした。

- 人間の承認境界。`contact_mode` は `always_ask` に固定で、サーバ側で強制される。エージェントは観察し、検知し、探索し、評価し、準備する——そして、止まる。止まらないコードパスは、書かれていない。
- 自律性は段階で渡す。Monitor ⊇ Search ⊇ Ask ⊇ Prepare。上の許可を切れば、下の自律動作は全部、構造的に止まる。保存時に正規化。クライアントの申告は信じない。
- プライバシーは、LLM の自己申告ではなく型システムで守る。非公開項目は本物の `visibility` フィールドを鍵に、フェイルクローズドでマスクされる。モデルが引用元について嘘をついても、何もアンマスクできない。
- データ境界＝プロセス境界。候補者は一人ずつ、隔離された推論で評価される。候補者間のリークは、起こしたくても起こせない。
- 監査もプライバシーを守る。承認前の記録は件数だけ——名前も自由記述もない。名前が現れるのは、人間が「はい」と言った後だ。そして配送は LLM のスコアだけでは認可されない。スコアが欠けても、数値でなくても、範囲外でも、フェイルクローズドで「接続なし」（ここは自前のレッドチームに突かれて固くした）。
- 正直に言うと、デモは1本の共有キーで動いている。審査員がひとつの URL で全フローを回せるようにするためだ。本番経路——IAP、従業員個人のプリンシパル、水平認可ガード——は実装もテストも済んでいて、残っているのはデプロイモードの1行だけ。

## ぶつかった課題（Challenges we ran into）

自律を「約束」ではなく「証明」にすること。冪等なスケジュールスイープ、フェイルクローズドな OIDC、件数だけの監査と実名の監査を分ける証跡——全部、これのためだ。
非公開の知識を、漏らさずに使わせること。関連性は確認される。内容は動かない。この同意フローが、いちばん難しかった。
力関係が見える UI。人間は大きく、エージェントは小さく。そして「未送信」が「送信済み」と見間違えようのない画面。

## 誇れる成果（Accomplishments we're proud of）

ノークリックのデモ。停滞したタスクが、人間の入力ゼロで「準備済みの紹介」になる——それでもシステムは、誰にも連絡できない。
「断る」が第一級の機能であること。静かで、見えなくて、望むなら寛大（代わりに資料を渡せる）。
マルチエージェントの LLM システムなのに、テストは全部オフラインで走ること。

## 学んだこと（What we learned）

エンタープライズエージェントの難所は、能力ではなかった。どこで止まるか、だった。このシステムの価値は全部、境界でできている。スイープが触れてよいもの。監査が記録してよいもの。候補者のエージェントが明かしてよいもの。そして、機械には決して許されない、ただ一つのクリック。

この学びは机上のものではない。設計は2ベンダーのモデルによる敵対的批評15ラウンドで叩き、提出前には3人の独立した監査者で自分たち自身をレッドチームした。監査者は実際に穴を見つけた——LLM のスコアが欠けたときに、配送が通ってしまう経路だ。フェイルクローズドは思想ではなく、回帰テストになった。

## 今後（What's next）

- 実データソースのコネクタ（カレンダー、メール、ドキュメント）。同じ可視性モデルの後ろに置く。インターフェースはもうある。
- 本番の個人アイデンティティ。IAP モードは実装済み・テスト済み。あとはデプロイフラグ1つ。
- エージェントの長期記憶。GEAP Memory Bank で、秘書が持つあなたの専門性の像は時間とともに深くなる。
- 相互運用。秘書を A2A / MCP で公開し、他のエージェントも同じ同意と監査の境界を通って紹介を依頼できるようにする。Agentspace / Spark 連携は成熟を見て。
